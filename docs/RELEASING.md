# Releasing Tomo TV

Maintainer release workflow. For day-to-day builds, see
[Getting started](../README.md#getting-started).

One command produces App Store artifacts for iOS, Mac Catalyst, then tvOS:

```bash
npm run archive -- <next-build>            # archive, export signed IPA/PKG files, validate
npm run archive -- <next-build> --upload   # also upload all three platforms and their listings
```

The argument is the build number (`CFBundleVersion`), stamped into `app.json`
before building so all three platforms share it. Keep increasing this shared
number; skipping ahead is fine, going backward is not. Prebuild regenerates `ios/` from
`app.json`, so that file is the only place the build number lives. Check the last
used number in App Store Connect before picking the next one.

- `.xcarchive`s land in `~/Library/Developer/Xcode/Archives/<date>/`, so they
  appear in Xcode Organizer for manual re-upload.
- Signed `.ipa`s, the Mac `.pkg`, and full build logs land in `build/release/<timestamp>/`
  (gitignored).

Validation and upload authenticate with an App Store Connect API key (App Store
Connect → Users and Access → Integrations, role App Manager). Keep the `.p8`
outside the repo and create a gitignored `.env.archive`:

```bash
ASC_KEY_ID=XXXXXXXXXX
ASC_ISSUER_ID=<issuer uuid from the same ASC page>
API_PRIVATE_KEYS_DIR=/absolute/path/to/dir/containing/AuthKey_XXXXXXXXXX.p8
```

Without API credentials the default mode skips App Store validation;
Xcode-managed signing uses the account configured in Xcode. `--upload` requires
the API credentials above.

## Mac setup and local validation

The `TomoTV-macOS` scheme is Mac Catalyst with the existing iPad interface, bundle
ID `dev.keiver.tomotv`, and keychain group. It targets macOS 13.4 or later, with
both Apple Silicon and Intel architectures. `npm run clear` prepares iOS, Mac,
then tvOS in the root workspace; `npm run clearmac` prepares only Mac. The generated
Mac project lives in `macos/`, with source-built Expo modules and its own Pods.
`npm run prebuild:all` and `npm run prebuild:mac` prepare projects without opening
Xcode or starting Metro. Use the Mac scheme's **My Mac (Mac Catalyst)** destination.
Both iOS and Mac projects hide **Mac (Designed for iPad)** in Xcode; Mac development
uses the Catalyst scheme. The Mac project also hides **Apple Vision (Designed for
iPad)**; iPhone and iPad remain the UIKit base destinations. The separate iOS
project retains its Apple Vision destination. These settings do not change App Store
availability. Under universal purchase, releasing the macOS version replaces the
iOS-on-Mac listing and updates its existing users to the Mac app.
Native prebuilds and archives share a lock: starting another command while one
is using the generated projects waits, so their temporary directory moves cannot
overwrite another platform.
Each app target depends explicitly on its own Pods project, so the shared
workspace cannot select an iOS library while building the Catalyst scheme.
All three Podfiles resolve Expo autolinking from their own directory, so Mac and
tvOS codegen writes into `macos/` and `tvos/` instead of the separate iOS tree.

iOS keeps Expo's precompiled modules. After CocoaPods integration,
`scripts/prebuilt-swift-imports.rb` removes source-module search paths for
framework-only pods, preventing old Swift modules in DerivedData from shadowing
the XCFramework interfaces. Source-built pods retain their search paths. The
iOS hook is regenerated by `plugins/withMacCatalyst.js`, including after `clear`.

During CocoaPods framework embedding, the Mac project repairs the versioned
layout of `ReactNativeDependencies.framework` before architecture stripping and
automatic signing. Privacy bundles stay in the version's `Resources` directory;
the framework root contains only `Versions` and the standard executable and
`Resources` links. The hook is generated by `plugins/withMacCatalyst.js` and
`scripts/catalyst-frameworks.rb`, and calls `scripts/fix-catalyst-framework.py`
for both Debug and Release, including after `clear` and during `archive`.

The Mac archive signs automatically, with the existing App Store Connect API key
and `-allowProvisioningUpdates`. The export signs manually: `scripts/exportOptions-macos.plist`
names the Apple Distribution certificate, the 3rd Party Mac Developer Installer
certificate for the package, and the `TomoTV Mac Catalyst App Store` profile.
The existing iOS/tvOS export settings stay in place.

Native build commands check the optional Metal Toolchain. If it is missing they
explain the requirement and ask before running
`xcodebuild -downloadComponent MetalToolchain`. The installer refreshes Xcode's
tool lookup cache and verifies the compiler. For explicit unattended consent:

```bash
npm run setup:xcode -- --install
# Or, for an unattended build:
TOMOTV_INSTALL_XCODE_COMPONENTS=1 npm run prebuild:all
```

Manual steps for the first Mac release:

1. In the existing TomoTV App Store Connect record, add **macOS** and open the
   version matching `app.json`. Keep the same app record and bundle ID for
   universal purchase. Complete Mac pricing, availability, review information,
   and any platform-specific declarations requested by App Store Connect.
2. Capture the nine screens listed by `npm run shots -- --list --device mac`.
   Put real 16:10 captures in `applestore/captures/mac/<shot-id>.png`, preferably
   2880×1800 or 2560×1600. Optional translations go in
   `applestore/captures/{de,fr,es}/mac/`; missing translations use the English
   capture with translated captions. Mac captures are manual; simulator capture
   skips Mac. Review the composed contact sheets before uploading.
3. Test on Apple Silicon and a supported Intel Mac: login/Quick Connect, saved
   credentials after relaunch, playback and seeking, audio/subtitle switching,
   Live TV, downloads/offline playback, books, keyboard/mouse, resizing, and
   fullscreen. Test an upgrade from the existing iPad app running on Mac with
   real saved settings, keychain credentials, and downloads. A universal build
   verifies compilation; it does not replace the Intel hardware check.
4. Review the Mac build in TestFlight and submit it manually in App Store Connect.

Apple references: [adding a platform](https://developer.apple.com/help/app-store-connect/create-an-app-record/add-platforms),
[automatic distribution signing](https://help.apple.com/xcode/mac/current/en.lproj/devff5ececf8.html),
and [Mac screenshot sizes](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications).

Local release checks:

```bash
npm run test:release
npm run shots -- --check-captures
npm run shots -- --render
npm run shots:upload -- --dry-run
npm run meta:upload -- --check
```

`archive --upload` checks App Store versions, text, and real captures before
building. It composes directly from `captures/`, rejects placeholder/stale
screenshots, uploads Mac screenshots to `APP_DESKTOP`, and selects the exact
shared build number after processing. The Mac PKG verification checks the
installer/app signatures, bundle version, sandbox networking, and both Catalyst
architectures. Initial Mac versions omit What's New because Apple does not
accept that field on a platform's first release; later Mac releases require it.

FFmpeg's Catalyst slices belong to `ffmpeg-n8.1.3-tomo.7`. Confirm iOS, Mac
Catalyst and tvOS work locally before publishing that release. The checked-in lock must contain the
SHA256 checksums of those exact ZIPs. Publishing/pushing remains a maintainer
action; building locally does neither.

To install locally built ZIPs before that release exists, first write their real
checksums into `packages/tomo-engine/ffmpeg-lock.json`, then run
`TOMO_FFMPEG_ARTIFACTS_DIR=.ffmpeg-build/dist npm run fetch:ffmpeg`. This uses the
same checksum verification as downloading the published release.

## The listing

`--upload` carries the listing too, in every store language: `npm run shots -- --render` and
`npm run shots:upload` for the screenshots, then `npm run meta:upload` for the
text. Both read the same API key.

The text comes from the paste blocks in
[`memories/CLAUDE-apple-store-metadata.md`](../memories/CLAUDE-apple-store-metadata.md),
which that file declares canonical. Name and subtitle go to the app info,
description, keywords, promotional text and What's New to the version. A missing
What's New for the version in `app.json` stops the offline check; during upload,
the field is omitted for a platform's first release.

Before a release, write the English What's New into that document and translate
it with the local model:

```bash
npm run notes                 # draft every language, print, write nothing
npm run notes -- --write      # and put the blocks back into the document
npm run meta:upload -- --dry-run
```

A block the document already holds is never rewritten, so the run above only
drafts what is missing; `npm run archive -- <build> --upload --notes` runs it
before the listing text goes up. `--redo` drafts
over the notes again, `--redo promo` over the promotional text after its English
changes, `--redo all` over both. `npm run notes -- --show` prints every block the
document holds and calls nothing.

`npm run notes` needs ollama on `127.0.0.1:11434`; nothing leaves the machine and
nothing is billed. It checks each draft against the glossary, the register and
the store limit, and hands a failing one back to the model with what was wrong.
A draft it accepts still needs a native reader.
